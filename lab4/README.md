# Лабораторная работа №4. Динамические библиотеки

Курс «Операционные системы», вариант 10.

Две динамические библиотеки с одинаковым набором функций и две программы, которые подключают их по-разному.

## Что реализовано

Функции, которые есть в обеих библиотеках:

```c
float cos_derivative(float a, float dx);  // производная cos(x) в точке a
int   gcd(int a, int b);                  // наибольший общий делитель
```

| | `lib1` | `lib2` |
|---|---|---|
| `cos_derivative` | `(cos(a + dx) - cos(a)) / dx` | `(cos(a + dx) - cos(a - dx)) / (2 * dx)` |
| `gcd` | алгоритм Евклида | перебор делителей |

Программы:

| Программа | Как подключает библиотеку |
|---|---|
| `prog1` | при сборке (линковка), всегда использует `lib1` |
| `prog2` | во время работы через `dlopen`, может переключаться между `lib1` и `lib2` |

## Сборка

Проект собирается на macOS:

```bash
make          # собрать всё
make clean    # удалить собранные файлы
```

После сборки в папке появятся `lib1.dylib`, `lib2.dylib`, `prog1` и `prog2`.

## Запуск

Запускать нужно из корня проекта, потому что `prog2` ищет библиотеки по путям `./lib1.dylib` и `./lib2.dylib`.

```bash
./prog1
./prog2
```

## Команды

| Ввод | Что делает |
|---|---|
| `0` | переключает библиотеку (только в `prog2`) |
| `1 a dx` | считает производную cos в точке `a` с приращением `dx` |
| `2 a b` | считает НОД чисел `a` и `b` |

Выход: `Ctrl+D`.

## Пример работы `prog2`

```
1 10 20      →  0.049666   (lib1)
2 10 20      →  10
0                          (переключились на lib2)
1 10 20      →  0.024833   (lib2)
2 10 20      →  10
```

Результат производной изменился после команды `0`, значит библиотека действительно сменилась. НОД одинаковый, потому что обе реализации верные и отличаются только скоростью.

## Чем отличаются две программы

| | `prog1` | `prog2` |
|---|---|---|
| Библиотека выбирается | при сборке | во время работы |
| Сменить реализацию | пересобрать | команда `0` |
| Нужен `lib.h` | да | нет |
| Видна в `otool -L` | да | нет |

Проверить зависимости можно так:

```bash
otool -L prog1    # есть @rpath/lib1.dylib
otool -L prog2    # только системные библиотеки
```

## Заметки

- Ввод и вывод сделаны через `read` и `write`, без `printf`, `scanf` и `fgets`.
- Если библиотека не загрузилась, `prog2` пишет ошибку и остаётся на текущей.
- На Linux нужно заменить `-dynamiclib` на `-shared`, расширение `.dylib` на `.so`, а при сборке `prog2` добавить `-ldl`.
